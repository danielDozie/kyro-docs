# `@kyro-cms/mcp`

::: warning Experimental / Beta
`@kyro-cms/mcp` is in active development. Tools, prompt templates, and resource URIs (`kyro://...`) will evolve as the Model Context Protocol ecosystem standardizes.
:::

The `@kyro-cms/mcp` package provides an official Model Context Protocol (MCP) server for Kyro CMS. It allows AI development tools—including Claude Desktop, Cursor, Antigravity, and GitHub Copilot—to interface directly with your content models, schemas, and live database adapters.

## Overview

The Model Context Protocol establishes a secure, standardized connection between local or hosted AI assistants and your development environment. Through `@kyro-cms/mcp`, AI assistants can:

- Introspect collection structures, field types, validation rules, and relationships.
- Query and mutate content documents safely within defined permission boundaries.
- Generate type-safe Astro frontends, layouts, and Content Layer loaders tailored to your schemas.
- Validate `kyro.config.ts` configuration files and detect schema drift.

## Installation

You can run the server directly using `npx` or install it into your project dependencies:

```bash
pnpm add -D @kyro-cms/mcp
```

## Running the Server

### Direct Command Line Interface

To run the MCP server over standard input/output (`stdio`):

```bash
npx @kyro-cms/mcp --config ./kyro.config.ts
```

### CLI Flags

| Flag | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--config`, `-c` | `string` | `./kyro.config.ts` | Path to the Kyro configuration file. |
| `--port`, `-p` | `number` | `3001` | Port number when running in Server-Sent Events (SSE) mode. |
| `--transport`, `-t` | `"stdio" \| "sse"` | `"stdio"` | Communication transport mode. |
| `--read-only` | `boolean` | `false` | Disable mutation tools (`mutate_document`). |

## Client Configuration

### Cursor IDE

Add the server to your project or workspace configuration in `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "kyro-cms": {
      "command": "npx",
      "args": ["-y", "@kyro-cms/mcp", "--config", "./kyro.config.ts"]
    }
  }
}
```

### Claude Desktop

Add the following configuration to your `claude_desktop_config.json` file:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`
- **Linux**: `~/.config/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "kyro-cms": {
      "command": "node",
      "args": [
        "/path/to/project/node_modules/@kyro-cms/mcp/dist/bin.js",
        "--config",
        "/path/to/project/kyro.config.ts"
      ]
    }
  }
}
```

## Available Tools

The MCP server exposes the following specialized tools to connected AI models:

### 1. `get_schema`

Retrieves structural metadata for all registered collections or a specific collection.

**Input Parameters:**
- `collection` *(optional, string)*: Slug of a specific collection. If omitted, returns all collections.

**Example AI Prompt:**
> "Inspect our blog collection schema and tell me what fields are required."

### 2. `query_collection`

Executes structured, type-safe queries against the configured database adapter.

**Input Parameters:**
- `collection` *(required, string)*: Collection slug (e.g. `"posts"`).
- `filter` *(optional, object)*: Key-value filter conditions.
- `limit` *(optional, number)*: Number of records to return (default: `10`, max: `100`).
- `sort` *(optional, string)*: Sort expression (e.g. `"-createdAt"`).
- `populate` *(optional, array)*: Relationship field names to expand.

**Example AI Prompt:**
> "Retrieve the 5 most recent published products in the electronics category."

### 3. `mutate_document`

Creates, updates, or soft-deletes documents in the target collection.

**Input Parameters:**
- `collection` *(required, string)*: Target collection slug.
- `action` *(required, `"create" | "update" | "delete"`)*: Operation type.
- `id` *(required for update/delete, string)*: Document identifier.
- `data` *(optional, object)*: Payload containing field values.

**Example AI Prompt:**
> "Create a new draft post titled 'Getting Started with Astro and Kyro' in the posts collection."

### 4. `generate_astro_component`

Generates Astro components (`.astro`), page routes, or Content Layer loaders that align with the collection's field definitions.

**Input Parameters:**
- `collection` *(required, string)*: Collection slug.
- `componentType` *(required, `"page" | "card" | "list" | "detail"`)*: Target component pattern.
- `framework` *(optional, `"astro" | "react" | "vue"`)*: Output syntax (default: `"astro"`).

**Example Output Generated by the AI:**

```astro
---
import { kyro } from "../lib/kyro";

interface Props {
  slug: string;
}

const { slug } = Astro.params;
const post = await kyro.collection("posts").findOne({
  where: { slug: { equals: slug } },
  populate: ["author", "category", "featuredImage"],
});

if (!post) {
  return Astro.redirect("/404");
}
---

<article class="max-w-3xl mx-auto py-12 px-4">
  <header class="mb-8">
    <span class="text-xs font-semibold text-emerald-600 uppercase tracking-wider">
      {post.category?.name}
    </span>
    <h1 class="text-4xl font-extrabold text-zinc-900 dark:text-white mt-2">
      {post.title}
    </h1>
    <p class="text-sm text-zinc-500 mt-2">
      By {post.author?.name} · {new Date(post.publishedAt).toLocaleDateString()}
    </p>
  </header>

  {post.featuredImage && (
    <img
      src={post.featuredImage.url}
      alt={post.featuredImage.alt || post.title}
      class="w-full h-80 object-cover rounded-2xl mb-8"
    />
  )}

  <div class="prose dark:prose-invert max-w-none">
    <Fragment set:html={post.content} />
  </div>
</article>
```

### 5. `diff_and_migrate_schema`

Compares active database tables against collection definitions in `kyro.config.ts`, generating Drizzle migration statements or SQLite schema patches.

### 6. `validate_config`

Performs static validation of field names, relationship targets, adapter options, and lifecycle hook declarations, highlighting potential syntax errors or missing targets.

## Dynamic Resources

The server registers URI-addressable resources that can be embedded directly into AI context windows:

| Resource URI | Description |
| :--- | :--- |
| `kyro://schema` | Complete schema definition for all collections and globals. |
| `kyro://collections/{slug}` | Field definitions, validation constraints, and hooks for a collection. |
| `kyro://globals/{slug}` | Singleton schema definitions (e.g. site settings, navigation). |
| `kyro://media/{id}` | Metadata and URLs for uploaded media assets. |

## Security Considerations

1. **Read-Only Mode**: In production or untrusted environments, launch with the `--read-only` flag to prevent automated document mutations.
2. **Environment Variables**: The MCP server loads credentials from your local `.env` file automatically. Never commit `.env` files containing production API keys.
3. **Database Safeguards**: Deletion operations perform soft-deletes or respect cascade protection rules configured in `kyro.config.ts`.
